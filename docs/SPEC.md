## 1. サービス概要

### 1.1 目的

コスメブランドの商品と美容系インフルエンサーをマッチングするプラットフォーム。
運営（Sunnyway）がブランドから商品掲載を預かり、**「ここに掲載すれば◯人のインフルエンサーが取り上げます」** という価値を中心に販売する。

### 1.2 提供価値

- **ブランドにとって**: 掲載するだけで目標人数のインフルエンサーによるSNS投稿（取り上げ）を獲得できる。投稿URL・リーチ実績はすべて運営が確認済み。
- **インフルエンサーにとって**: アプリから気になるコスメ案件に応募し、商品提供（ギフティング）や金銭報酬を受け取れる。
- **運営にとって**: ブランド向けの課金（4モデル併用可）とマッチングの仲介手数料で収益化。すべての案件・報酬・実績を一元管理できる。

### 1.3 利用者と権限（3者構成）

| 利用者 | 利用画面 | 権限 |
|---|---|---|
| **運営（Sunnyway）** | Web 管理コンソール（`/admin`） | 全権限。ブランド・商品・掲載・応募・報酬・インフルエンサーの管理 |
| **インフルエンサー** | スマホアプリ（PWA、`/app`） | 案件の閲覧・応募・投稿提出・報酬確認・自身のプロフィール管理のみ |
| **コスメブランド** | （ログインアカウントなし） | **管理画面へのアクセス権を持たない。** 運営が窓口となり代理管理する |

> ブランドは「ログインするユーザー」としてではなく、運営が管理する**データ**としてのみ存在します。
> 「ブランドに管理権限を渡さない」という要件を、権限設定ではなくデータ構造そのもので担保しています（アカウントが存在しないため、設定ミスによる権限漏えいが構造上発生しません）。

## 3. ビジネスモデル（実装済みの課金設計）

運営→ブランドへの課金は次の **4 モデル**をシステムに実装済み。掲載（キャンペーン）ごとに**複数併用**できます。

| モデル | 内容 | 設定箇所 |
|---|---|---|
| `MONTHLY` 月額掲載料 | ブランド単位の月額契約 | ブランドに月額（円）を設定 |
| `PER_CAMPAIGN` 掲載課金 | 掲載1件ごとの費用 | 掲載に費用（円）を設定 |
| `PERFORMANCE` 成果連動 | リーチ・投稿数に連動した課金 | 投稿ごとのリーチ実績を運営が確認・集計 |
| `SALES_COMMISSION` 販売手数料 | 売上に対する料率課金 | 掲載に料率（%）を設定 |

インフルエンサーへの**報酬タイプ**は案件ごとに設定：

| タイプ | 内容 |
|---|---|
| `GIFTING` | 現物提供（商品ギフティング） |
| `PAID` | 金銭報酬（1人あたりの金額を設定） |
| `BOTH` | 現物 + 金銭の併用 |
| `OTHER` | その他（発売イベント招待など） |

## 4. 業務フロー（案件のライフサイクル）

```
【運営】ブランド登録 → 商品登録 → 掲載作成(下書き) → 公開
                                                  │
【インフルエンサー】 さがす → 応募 ──────────────────┘
                      │
【運営】応募者を確認 → 採用 or 見送り（アプリへ自動通知）
                      │
【インフルエンサー】 商品受け取り → SNS投稿 → 投稿URL・リーチを提出
                      │
【運営】投稿チェック → 完了（報酬を記録・自動通知） or 差し戻し
```

### 4.1 掲載（キャンペーン）の状態

| 状態 | 意味 |
|---|---|
| `DRAFT` | 下書き（インフルエンサーには非公開） |
| `OPEN` | 募集中（アプリの「さがす」に表示） |
| `CLOSED` | 募集締切 |
| `COMPLETED` | 完了 |

### 4.2 応募の状態

| 状態 | 意味 | アプリでの表示 |
|---|---|---|
| `APPLIED` | 応募済み（運営の判断待ち） | 応募履歴 |
| `APPROVED` | 採用（投稿待ち） | 案件管理「やること」 |
| `SUBMITTED` | 投稿提出済み（運営チェック中） | 案件管理「チェック中」 |
| `COMPLETED` | 完了（報酬確定） | 案件管理「完了」 |
| `REJECTED` | 見送り | 応募履歴 |

- 同一案件への**二重応募はデータベース制約で禁止**。
- 採用時・完了時にはアプリ内通知を**自動送信**。
- 完了時には報酬の**取引記録（Transaction）を自動作成**し、インフルエンサーの取引履歴へ反映。

## 5. 画面仕様 — インフルエンサーアプリ（スマホ／タブレット PWA）

### 5.1 初回体験

| 画面 | 内容 |
|---|---|
| スプラッシュ | ブランドロゴ（マスコット）アニメーション |
| オンボーディング | サービス紹介 3 スライド（スキップ可） |
| 新規登録／ログイン | メール＋パスワード。登録時に SNS ハンドル・フォロワー数等を入力 |

### 5.2 さがす（ホーム）

- 特集バナー（月間アワード等のお知らせ枠）
- カテゴリフィルタ: すべて／スキンケア／メイクアップ／顔出し不要／報酬あり
- 媒体別セクション: Instagram Feed ／ Instagram Reels ／ TikTok
- 案件カード: 商品写真・ブランド名・タイトル・報酬・応募状況（応募数／募集人数）・締切・条件タグ・お気に入り（♥）・応募ボタン
- 通知ベル（未読件数バッジ付き）

### 5.3 案件詳細

- 商品写真・ブランド・依頼内容（投稿条件）・条件タグ・報酬・応募状況・締切
- 応募フォーム（応募時の一言メッセージ付き）／応募済み表示

### 5.4 案件管理

- 3 タブ: **やること**（投稿URL・リーチの提出フォーム）／**チェック中**／**完了**（確定報酬の表示）
- 応募履歴ページ（全応募の状態一覧）

### 5.5 メッセージ

- 運営（Sunnyway 公式)とのチャット形式のやり取り（吹き出しUI・送信フォーム）

### 5.6 通知

- 採用・完了などの通知一覧、未読管理・一括既読

### 5.7 マイページ

- 実績サマリー: 応募数・取り上げ数・累計報酬
- プロフィール（名前・自己紹介・フォロワー数）
- 住所（ギフティング商品の発送先）
- SNS連携（Instagram／TikTok）
- 振込先（金銭報酬の受け取り口座）
- 取引履歴（報酬の入金記録）
- 通知設定／使い方の再表示／ログアウト

## 6. 画面仕様 — 運営管理コンソール（`/admin`）

### 6.1 ダッシュボード

- KPI: 募集中の掲載・取り上げ件数・合計リーチ・報酬支払額・ブランド数
- **要対応キュー**: 提出済み（チェック待ち）の投稿一覧
- 最近の掲載・操作ログ（監査）

### 6.2 掲載管理

- 掲載の新規作成: ブランド・商品・タイトル・依頼内容・媒体・条件タグ・締切・募集人数（=「◯人が取り上げます」）・報酬タイプ／金額・課金モデル（複数選択）
- **掲載内容の編集**（全項目。商品を変更した場合はブランドも自動で追従）
- 状態変更（下書き→公開→締切→完了）
- 掲載詳細: 応募者一覧 → **採用／見送り** → 提出された投稿URL・リーチの**チェック → 完了（報酬記録）／差し戻し**

### 6.3 商品管理

- 商品の登録・**編集**・一覧（カテゴリ・参考価格・**商品画像のアップロード／差し替え対応**）

### 6.4 ブランド管理

- ブランドの登録・**編集**・一覧（担当者・連絡先・月額契約の金額設定・契約中／停止の切り替え）
- 担当者メールアドレスへの**メール送信**（宛先プリセット付き）

### 6.5 インフルエンサー管理

- 登録インフルエンサーの一覧（媒体・フォロワー数・実績）
- **認証バッジの付け外し**・個別メール送信・**全員への一斉メール**

### 6.6 メール送信

- 登録アドレス宛てのお知らせ送信（個別／ブランド担当者／**全インフルエンサーへ一斉送信**）
- 全送信内容を**送信履歴**として記録・一覧表示（送信済み／記録のみ／失敗）
- 送信プロバイダ（`RESEND_API_KEY`）を設定すると実送信。未設定環境では履歴への記録のみで安全に動作

## 7. データ構造（主要エンティティ）

| エンティティ | 役割 |
|---|---|
| User | ログインアカウント（役割: ADMIN／INFLUENCER） |
| InfluencerProfile | インフルエンサー情報（ハンドル・媒体・フォロワー・住所・振込先・SNS連携・お気に入り） |
| Brand | ブランド（運営が代理管理。月額契約金額を保持） |
| Product | 商品（カテゴリ・画像・参考価格） |
| Campaign | 掲載（媒体・タグ・募集人数・報酬設計・課金モデル・状態） |
| Application | 応募（状態・応募メッセージ・投稿URL・リーチ実績） |
| Transaction | 報酬の取引記録（金額・状態） |
| Message | 運営⇄インフルエンサーのメッセージ |
| Notification | アプリ内通知（未読管理） |
| AuditLog | 運営の全管理操作の監査ログ |
| MailLog | メール送信履歴（宛先・件名・本文・送信状態） |

## 8. セキュリティ

| 項目 | 実装内容 |
|---|---|
| 認証 | JWT を httpOnly Cookie に保存（JS から読み取り不可）。パスワードは bcrypt でハッシュ化 |
| アクセス制御 | ロールベース（RBAC）。ミドルウェア＋各ページ＋各操作（Server Action）の**三層でチェック** |
| ブランドの隔離 | ブランドにはログインアカウント自体が存在せず、管理画面へ到達する経路がない |
| 監査ログ | ブランド作成・採用・完了など、運営の管理操作をすべて記録 |
| 二重応募防止 | データベースの一意制約で同一案件への重複応募を禁止 |
| デモ資格情報 | 本番公開前に必ず変更（§10 参照） |

## 9. 対応環境・UI／パフォーマンス

### 9.1 レスポンシブ対応

| 幅 | レイアウト |
|---|---|
| スマートフォン | 下部タブバー（画面に固定追従）＋縦1カラム |
| タブレット（768px〜） | 左サイドレール＋本文、案件・管理カードは 2 カラムグリッド |
| ワイド（1024px〜） | サイドレール拡張（ロゴ＋ラベル表示）、案件は 3 カラムグリッド |

### 9.2 PWA

- ホーム画面に追加可能（専用アイコン・スプラッシュ）
- Service Worker によるオフラインシェル・主要画像のプリキャッシュ

### 9.3 デザイン

- 株式会社Sunnyway 公式サイトのブランドに準拠（カラー・タイポグラフィ・マスコットロゴ）
- マイクロアニメーション（画面遷移・カード出現・タップフィードバック・数値カウントアップ等）
- `prefers-reduced-motion`（視差効果を減らす設定）に対応

### 9.4 パフォーマンス最適化

- 画像の軽量化（合計 約261KB → 約76KB、**約71%削減**・画質劣化なし）
- 画面外画像の遅延読み込み（`loading=lazy`）・主要画像の先読み（preload）
