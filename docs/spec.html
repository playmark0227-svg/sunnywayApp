1サービス概要

1.1 目的

コスメブランドの商品と美容系インフルエンサーをマッチングするプラットフォーム。運営（Sunnyway）がブランドから商品掲載を預かり、「ここに掲載すれば◯人のインフルエンサーが取り上げます」という価値を中心に販売する。

1.2 提供価値

  • ブランド: 掲載するだけで目標人数のインフルエンサーによるSNS投稿（取り上げ）を獲得。投稿URL・リーチ実績はすべて運営の確認済み。
  • インフルエンサー: アプリから気になるコスメ案件に応募し、商品提供（ギフティング）や金銭報酬を受け取れる。
  • 運営: ブランド向け課金（4モデル併用可）とマッチング仲介で収益化。案件・報酬・実績を一元管理。

1.3 利用者と権限（3者構成）

利用者利用画面権限
運営（Sunnyway）Web 管理コンソール（/admin）全権限。ブランド・商品・掲載・応募・報酬・インフルエンサーの管理
インフルエンサースマホアプリ（PWA、/app）案件の閲覧・応募・投稿提出・報酬確認・自身のプロフィール管理のみ
コスメブランド（ログインアカウントなし）管理画面へのアクセス権を持たない。運営が窓口となり代理管理
設計ポイント: ブランドは「ログインするユーザー」ではなく、運営が管理するデータとしてのみ存在します。「ブランドに管理権限を渡さない」という要件を権限設定ではなくデータ構造で担保しているため、設定ミスによる権限漏えいが構造上発生しません。

3ビジネスモデル（実装済みの課金設計）

運営→ブランドへの課金は次の 4 モデルをシステムに実装済み。掲載（キャンペーン）ごとに複数併用できます。

モデル内容設定箇所
MONTHLY 月額掲載料ブランド単位の月額契約ブランドに月額（円）を設定
PER_CAMPAIGN 掲載課金掲載1件ごとの費用掲載に費用（円）を設定
PERFORMANCE 成果連動リーチ・投稿数に連動した課金投稿ごとのリーチ実績を運営が確認・集計
SALES_COMMISSION 販売手数料売上に対する料率課金掲載に料率（%）を設定

インフルエンサーへの報酬タイプは案件ごとに設定します。

タイプ内容
GIFTING現物提供（商品ギフティング）
PAID金銭報酬（1人あたりの金額を設定）
BOTH現物 + 金銭の併用
OTHERその他（発売イベント招待など）

4業務フロー（案件のライフサイクル）

【運営】ブランド登録 → 商品登録 → 掲載作成（下書き）→ 公開
【インフルエンサー】さがす → 応募
【運営】応募者を確認 → 採用 or 見送り（アプリへ自動通知）
【インフルエンサー】商品受け取り → SNS投稿 → 投稿URL・リーチを提出
【運営】投稿チェック → 完了（報酬を記録・自動通知） or 差し戻し

4.1 掲載（キャンペーン）の状態

状態意味
DRAFT 下書きインフルエンサーには非公開
OPEN 募集中アプリの「さがす」に表示
CLOSED 募集締切新規応募の受付を終了
COMPLETED 完了掲載をクローズ

4.2 応募の状態

状態意味アプリでの表示
APPLIED応募済み（運営の判断待ち）応募履歴
APPROVED採用（投稿待ち）案件管理「やること」
SUBMITTED投稿提出済み（運営チェック中）案件管理「チェック中」
COMPLETED完了（報酬確定）案件管理「完了」
REJECTED見送り応募履歴
  • 同一案件への二重応募はデータベース制約で禁止。
  • 採用時・完了時にはアプリ内通知を自動送信。
  • 完了時には報酬の取引記録（Transaction）を自動作成し、インフルエンサーの取引履歴へ反映。

5画面仕様 — インフルエンサーアプリ（スマホ／タブレット PWA）

5.1 初回体験

画面内容
スプラッシュブランドロゴ（マスコット）アニメーション
オンボーディングサービス紹介 3 スライド（スキップ可）
新規登録／ログインメール＋パスワード。登録時に SNS ハンドル・フォロワー数等を入力

5.2 さがす（ホーム）

  • 特集バナー（月間アワード等のお知らせ枠）
  • カテゴリフィルタ: すべて／スキンケア／メイクアップ／顔出し不要／報酬あり
  • 媒体別セクション: Instagram Feed ／ Instagram Reels ／ TikTok
  • 案件カード: 商品写真・ブランド名・タイトル・報酬・応募状況（応募数／募集人数）・締切・条件タグ・お気に入り（♥）・応募ボタン
  • 通知ベル（未読件数バッジ付き）

5.3 案件詳細

  • 商品写真・ブランド・依頼内容（投稿条件）・条件タグ・報酬・応募状況・締切
  • 応募フォーム（応募時の一言メッセージ付き）／応募済み表示

5.4 案件管理

  • 3 タブ: やること（投稿URL・リーチの提出フォーム）／チェック中／完了（確定報酬の表示）
  • 応募履歴ページ（全応募の状態一覧）

5.5 メッセージ／5.6 通知

  • 運営（Sunnyway 公式）とのチャット形式のやり取り（吹き出しUI・送信フォーム）
  • 採用・完了などの通知一覧、未読管理・一括既読

5.7 マイページ

  • 実績サマリー: 応募数・取り上げ数・累計報酬
  • プロフィール（名前・自己紹介・フォロワー数）／住所（ギフティング発送先）／SNS連携（Instagram・TikTok）／振込先／取引履歴／通知設定／使い方の再表示／ログアウト

6画面仕様 — 運営管理コンソール（/admin）

6.1 ダッシュボード

  • KPI: 募集中の掲載・取り上げ件数・合計リーチ・報酬支払額・ブランド数
  • 要対応キュー: 提出済み（チェック待ち）の投稿一覧
  • 最近の掲載・操作ログ（監査）

6.2 掲載管理

  • 新規作成: ブランド・商品・タイトル・依頼内容・媒体・条件タグ・締切・募集人数（=「◯人が取り上げます」）・報酬タイプ／金額・課金モデル（複数選択）
  • 状態変更（下書き→公開→締切→完了）
  • 掲載詳細: 応募者一覧 → 採用／見送り → 提出された投稿URL・リーチのチェック → 完了（報酬記録）／差し戻し

6.3 商品管理／6.4 ブランド管理／6.5 インフルエンサー管理

  • 商品: 登録・一覧（カテゴリ・参考価格・商品画像のアップロード対応）
  • ブランド: 登録・一覧（担当者・連絡先・月額契約の金額設定）
  • インフルエンサー: 一覧（媒体・フォロワー数・実績・認証バッジ）

8セキュリティ

項目実装内容
認証JWT を httpOnly Cookie に保存（JS から読み取り不可）。パスワードは bcrypt でハッシュ化
アクセス制御ロールベース（RBAC）。ミドルウェア＋各ページ＋各操作（Server Action）の三層でチェック
ブランドの隔離ブランドにはログインアカウント自体が存在せず、管理画面へ到達する経路がない
監査ログブランド作成・採用・完了など、運営の管理操作をすべて記録
二重応募防止データベースの一意制約で同一案件への重複応募を禁止
デモ資格情報本番公開前に必ず変更（§10 参照）

9対応環境・UI／パフォーマンス

9.1 レスポンシブ対応

幅レイアウト
スマートフォン下部タブバー（画面に固定追従）＋縦1カラム
タブレット（768px〜）左サイドレール＋本文、案件・管理カードは 2 カラムグリッド
ワイド（1024px〜）サイドレール拡張（ロゴ＋ラベル表示）、案件は 3 カラムグリッド

9.2 PWA ／ 9.3 デザイン ／ 9.4 パフォーマンス

  • ホーム画面に追加可能（専用アイコン・スプラッシュ）。Service Worker によるオフラインシェル・主要画像のプリキャッシュ
  • 株式会社Sunnyway 公式サイトのブランドに準拠（カラー・タイポグラフィ・マスコットロゴ）
  • マイクロアニメーション（画面遷移・カード出現・タップフィードバック・数値カウントアップ等）。prefers-reduced-motion に対応
  • 画像の軽量化（合計 約261KB → 約76KB、約71%削減・画質劣化なし）。画面外画像の遅延読み込み・主要画像の先読み
